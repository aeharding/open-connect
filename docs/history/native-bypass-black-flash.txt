2026-11-13. Saved sources/logs/video only; no target changes or restart.

Finding
The v2 patch disposes the native intro too early. This is a concrete lifecycle
ordering defect in the current bypass, not evidence that home fundamentally
needs a black loading screen. Logs + video + actual renderer code align.
Live-demo candidate remains installed/running, root RO; no new patch built.

Recommended next prototype
Keep native bypass decision and OEM continuation/focus/exit hooks. Move disposal
out of the pre-dispatch wrapper. Use the outgoing Intro template's actual
post-transition/noLongerDisplayed lifecycle to send the existing DisposeIntroVideo
event after the new screen is rendered and old surfaces are hidden.
A narrowly scoped frontend lifecycle hook plus the native change is justified:
it connects rendering completion to native resource cleanup, rather than hiding
pixels or estimating a delay. Bound it to the bypassed Intro handoff and make
cleanup once/idempotent; preserve stock unsupported paths and failure behavior.
Do not just remove disposal (leaks player/resources), sleep a fixed duration,
globally speed up CSS, or suppress renderer completion.

Expected difficulty: a small, testable two-part lifecycle change, rather than
a new compositor. No runtime success claimed yet. Validate actual destination
visible before intro unregister, cleanup completed, no warning/black interval,
normal heartbeat and continuation, independent undo. Existing renderer already
supplies the relevant completion point. If a residual fade remains after ordering
is corrected, evaluate only that specific Intro-to-destination transition.
