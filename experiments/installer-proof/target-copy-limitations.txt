What the host model actually covers
- Full bytes/hash/length and permission mode. Snapshot image files are0600; journal
  descriptors carry intended target mode. Atomic replacement fchmod sets that mode.
- regular() uses lstat and requires regular type, st_nlink==1 and bounded size:
  final-component symlinks and hardlinks are REFUSED, not preserved/reconstructed.
- atomic() creates temporary file in destination parent, writes+flushes+fsyncs it,
  os.replace() to the destination, then opens+fsyncs that parent directory. This
  is same-parent host replacement for target, image and journal files separately.

What remains outside the model
- No original UID/GID capture/check/fchown. New inode ownership follows host process/
  parent defaults. No ownership, ACL/xattr, timestamps, inode identity or hardlink
  graph restoration. Host-copy0755 is not proof of restored CMU metadata.
- No race-free pathname walk/O_NOFOLLOW/dirfd or atomic compare-and-swap. lstat and
  reads/replacement are separate; single writer/private directory is an assumption.
- No atomic multi-file transaction. Journal and target are separate replacements;
  mkdir(.proof) does not explicitly fsync its parent at creation. Process-exit
  checkpoints do not test arbitrary power cuts, directory loss or storage faults.
- Host fsync/rename calls do not establish BusyBox cp/mv behavior, RelFS atomicity,
  fsync support/durability, mount procedure or target recovery/access guarantees.
