PROPOSED WORK FOR THE NEXT FEW DAYS; NOT STARTED BY THIS PLAN

Day 1: Make the Mac-side operating contract concrete, without CMU modification.

A. Single owner for UART and camera.
   Keep one named operator terminal as the only process allowed to open the
   physical UART. The coordinator queues requests with hc send; research agents
   use saved logs, source extracts, and frames. No separate screen/cu session,
   passive logger, or second command helper may open the UART simultaneously.
   Use an application lease keyed by adapter serial A9048JM0, recording owner
   terminal, host PID, request ID, and acquisition time. Reclaim a stale lease
   only after checking the owning process and actual serial handles, including
   /dev/tty.usbserial-A9048JM0. pySerial exclusive=True is a useful additional
   advisory guard; do not treat it as a universal lock against other tools.
   Camera ownership should likewise prevent concurrent captures/exposure races.
   Handoff includes pending commands, prompt/identity evidence, owned PIDs, and
   evidence paths, followed by confirmed port release. Do not log out the CMU.

B. Console state and identity protocol.
   Re-enumerate by VID/PID AND serial for every acquisition; fail if absent or
   ambiguous rather than selecting a different serial adapter. Apply the known
   UART settings before open, with RTS/DTR inactive and no break/reset action.
   Begin with a short receive-only window. Classify login prompt, password
   prompt, shell prompt, foreground application, boot output, or unknown state.
   The existing helper sends CR before its prompt check and accepts a broad
   #/$ prompt regex. This is adequate for the currently known shell checks but
   needs a guarded state layer before general unattended use. Silence alone
   does not justify Enter, credentials, Ctrl-C, or arbitrary shell commands.
   When the known shell is established, send a short uniquely marked id check;
   require the fresh response, expected uid, command completion, and prompt.
   Match version fields from /jci/version.ini when establishing a session:
   known installed firmware is 55.00.750B, cmu150_NA; NEXT_VER is not installed.
   Do not infer root merely from #. If login becomes necessary, stop that
   transaction and use only the already authorized credential procedure after
   distinguishing login from password state; never send credentials blindly.
   Preserve credential secrecy in future logs. No account changes are needed.

C. Completion and evidence, rather than fixed sleeps.
   The current helper's status 'command capture finished' means its read window
   ended, not that the CMU command succeeded. Plan a wrapper with unique begin
   and end markers, captured shell exit status, expected output, and a returned
   prompt. Account for asynchronous CMU log lines and terminal line wrapping;
   neither an echoed command nor a marker embedded in that echo is completion.
   Keep raw RX bytes and timestamped RX/TX events as the source of truth.
   A future continuous broker could avoid gaps between one-shot command logs;
   do not claim this turn captured a continuous boot/runtime trace.
   Validate any new host parsing/lease code against saved transcripts and
   pseudo-terminals before proposing a new live bench action.
