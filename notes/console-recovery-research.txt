WHY ETX CAN LEAVE THE CONTINUATION
libbb/lineedit.c2088-2093 documents return0 for Ctrl-C, negative for empty-line EOF.
Lines2153-2163 disable tty ISIG during editing;2496-2503 recognize configured
VINTR, clear only the current line and return0 without appending a newline.
shell/ash.c9641-9652 retries read_line_input after0 if no SIGINT trap is installed.
That retry does not unwind the parser holding earlier quoted input. The observed
CRLF and renewed continuation fit this path; exact vendor behavior remains unknown.
Repeated03 is therefore not a justified recovery loop.

WHY EMPTY-LINE EOF IS DIFFERENT
lineedit.c2505-2519:configured VEOF on nonempty input deletes at the cursor;
on empty input it returns negative with errno0.
ash.c9653-9657 maps that result to EOF;9746-9752 turns it into parser PEOF.
ash.c11288-11299 rejects an unterminated quote with a syntax error;1233-1242
raises EXERROR. cmdloop at12157-12174 evaluates the pending tree only after
parsecmd returns successfully. The incomplete quoted command therefore fails
before that pending evaltree in the stock source.
Interactive top-level handling at13109-13139 calls reset and resumes state4.
reset13056-13072 clears input/parser buffers and redirections; state4 at13208-13210
re-enters cmdloop. Conditions differ for noninteractive/nested shells or other
continuation types; a greater-than prompt alone is not sufficient evidence.

WHY CLEAR THE CURRENT LINE FIRST
The visible trailing0 leaves current-line emptiness uncertain. Bare04 might only
delete a character. lineedit.c2239-2243 moves to end on Ctrl-E;2295-2303 clears
everything before cursor on Ctrl-U. Together these clear the entire current
editable line without submitting it. Ctrl-U alone can leave text after cursor.
Stock source initializes edit mode for each read; vendor/editor mode remains a
limit. None of these control bytes closes a quote or supplies a shell newline.
