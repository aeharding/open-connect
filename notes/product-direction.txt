USER GOALS
1. A dedicated headless Mac + Mazda CMU bench that agents can develop on, operate
and clean up autonomously24/7. The user supplies physical resources; agents own
software execution, routine decisions, evidence and cleanup. Routine bench actions
do not need individual user approval. Physical dependencies are recorded rather
than handed back as button-press/wiring tasks. This goal does not mean a new
background schedule or unattended task has been activated.
2. Improve Mazda Connect responsiveness and reliability while preserving the OEM
feel. Investigate cold-start wireless CarPlay instability on the user's car:
it works but is unstable. RAM overload is a hypothesis, not a measured cause or a
claim that all CMUs/adapters behave the same way. Keep hardware/firmware-specific
compatibility explicit.
3. Optional a la carte features, such as deprecated-app cleanup, disclaimer changes
or wireless improvements. Users should choose what they install and understand
compatibility, effects and reversibility; no mandatory collection of unrelated mods.
4. Robust deliberate USB maintenance: install, reconfigure, upgrade, repair and
uninstall. The original installation stick must never be required again. Supporting
older packages needs an explicit compatibility policy; no "any version" promise.
5. A contribution-friendly open-source project. Publish reverse-engineering
knowledge that is useful even without installing anything. Keep it in the same
versioned repository as code, with firmware/date/source, experiment, test and
rollback context so others can review freshness and reproduce the supported scope.
Keep full OEM snapshots private/ignored; publish independent logic, observations,
source hashes and minimal necessary references rather than whole OEM files.
6. Shared installer infrastructure owns backup, journal and restore. Each feature
declares its changes, how to verify them and how to undo them. Bench serial rescue
does not establish validated end-user USB recovery; no "impossible to brick" claim.
Exact original backups mean as-found installed bytes, not proved pristine factory
OEM; restoring a baseline can restore earlier modifications as well.
Public release and the user's personal car are separate from routine test-bench
development and need their own demonstrated scope.

PROPOSED DESIGN CHOICES — ROOT PROPOSALS, NOT DECISIONS
- A host-only shared-installer model with a harmless full-cycle/interruption-test
fixture can remain experimental infrastructure. Disclaimer bypass is now the user's
first REAL feature; a broad catalog/configurator remains later/open.
- Measure cold-start RAM, Wi-Fi, Bluetooth and CarPlay timings before removing

OPEN DESIGN / COMPATIBILITY QUESTIONS
- Where configuration runs: a computer configurator versus a commander-only CMU
interface is not final. Deliberate USB maintenance is preferred; the interface and
packaging are still open. Avoid assuming a computer is always required or that the
physical commander has already been validated on this bench.
- Package identity/versioning, supported upgrade/downgrade paths, older-package
compatibility, dependency conflicts and feature-specific rollback guarantees.
"No original stick" requires independently reconstructible maintenance, not a
promise to execute arbitrary historical packages.
- Recovery coverage after partial installation, interrupted writes, missing/corrupt
backups or firmware mismatch. Distinguish ordinary undo/repair from actual firmware
or storage recovery. Local hashes/Git are not an independent second copy.
- How to preserve OEM startup/frontend lifecycle and measure improved responsiveness
and wireless reliability without trading away existing USB/SD/navigation behavior.
