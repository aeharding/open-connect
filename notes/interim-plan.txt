COORDINATION AND OWNERSHIP
Coordinator: maintain priorities, dependency/decision log, agent scopes, source
index and acceptance evidence. Use Herdr's hc API/CLI for all agent control,
communication, file operations and program execution.
Bench operator: the sole UART owner; performs all live shell, UI and camera work.
Development agent: versioned host tools and offline tests; live tests are handed
to the operator. Research agent: sources, applicability, verified findings and
open questions; no live port access.
Roles may be assigned in successive tasks rather than kept running permanently.
Each task states allowed paths, allowed bench actions, expected artifact and how
to report completion. Agents do not spawn further agents without a scoped task.
The user will not press buttons, dismiss dialogs, reposition hardware or rewire.
Agents own software cleanup. Physical operations outside software capability are
recorded as hardware dependencies, never assigned back to the user.

RESEARCH STORAGE DESIGN
Keep the existing evidence folders. Add these only as implementation proceeds:
  research/index.tsv             authoritative searchable catalog with topic tags
  research/index.txt             human entry point generated from catalog/status
  research/sources/              permitted source snapshots and source manifest
  research/facts.jsonl           claims with evidence IDs, scope and verification
  research/hypotheses.jsonl      open ideas, proposed tests and disposition
  research/decisions/             decision, alternatives, reason, applicable build
  experiments/<id>/              versioned definition/code and cleanup procedure
  tests/fixtures/                sanitized, small captured-output fixtures
  runs/<id>/manifest.json        links to logs/captures, code revision and checksums

Source record: source ID, title/author, exact URL or local reference, retrieval
date, revision/content hash, relevant section/page, hardware/firmware scope,
what it supports, conflicts and whether it is superseded.
Experiment record: question, prerequisites, firmware and tool revision, command
list, expected result, raw evidence paths/hashes, actual outcome, interpretation,
cleanup/rollback result and next question.
End each session by updating the index, findings, decisions, experiment status
and handoff. An untested idea stays a hypothesis; missing output stays unknown.
Git holds code, instructions, summaries, source manifests, decisions and small
sanitized fixtures. Large/raw/private captures, credentials, copied device
configuration and binary dumps stay in local evidence storage with Git-tracked
manifests/hashes. Never publish device dumps or push a remote repository by default.
