CONCRETE LIFETIME CONTRACT SUPPORTED BY THESE SOURCES
1. Only system/Disclaimer's ready hook: verify matching context/sequence/template,
   capture that exact instance and its root node. No template prototype/global CSS,
   broad Dialog3 selector, persistent ID rule, or current-pointer cleanup later.
2. Apply the selected paint-only mask before normal reveal; separately verify
   generated transitions/CSS and child methods cannot defeat the chosen property.
   A fresh node does not establish that visibility/opacity/display is safe.
3. Keep that node masked through outgoing transition, noLongerDisplayed, child
   cleanup and framework detach, including any retained snapshot reference.
   Do not restore its original style while it can still paint. Because the next
   template allocates a new root, no unhide/reset is needed to make it visible.
4. Let OEM lifetime disposal retire the old masked node; release only our reference
   when appropriate. Do not remove/reparent it ourselves or stall callbacks to hide
   it. Preserve DisposeIntroVideo, initialization, Timeout/Agree/pause/teardown and
   the stock heartbeat. This is a per-node lifetime contract, not a final patch.

SYNTHESIS LIFETIME CRITIQUE — t13 proposed document-owned opacity shield
No concrete lifetime contradiction found. One document-lifetime author-important
opacity0 rule scoped to an opaque marker on ONLY captured system/Disclaimer roots
fits the proven fresh-object/fresh-root model. Retired/snapshot roots remain marked;
future dialogs allocate unmarked roots. A single rule avoids per-entry rule growth
and modulo999 ID ownership errors. This is a design critique, not an implementation
or proof of CSS/compositor behavior.

Conditions: use an opaque attribute or non-Transitions_ marker (the latter prefix
is stripped by Transitions877-900); wrap only the exact instance's restore method,
never its prototype; preserve original receiver/arguments/result/error behavior and
invoke it exactly once. Reassert only on the same captured root, including failure
paths without swallowing the original error. Remove only conflicting inline-
important opacity for that owned root, not arbitrary styles. Root replacement is
an unsupported identity change, not permission to adopt another root by selector.
Do not keep a document-wide JS list that retains every retired node. Leave masks
on retired nodes; no cleanup unhide is required for a newly allocated next dialog.

Precision: callback-before-removal source order alone does NOT prove an intermediate
paint occurs during normal completion. Both are in the same framework completion
function. It does mean noLongerDisplayed is not a post-detach guarantee; exceptional
cleanup or retained/referenced DOM makes early unhide an unnecessary risk. Keeping
the old node masked avoids depending on that timing entirely.

T13 reports actual stock route Crossfade IntroAnimation->Disclaimer and
Disclaimer->HomeScreen, with incoming-root animationend. The proposed shield must
leave normal classes/animation timing/completion active and also handle alternate
Snap's known ordinary inline opacity1 write. Actual opacity priority, descendant/
control side effects and animationend behavior under the shield still require
focused future validation; no source-only no-flash or event guarantee here.
No further source request, test, code or target action for this critique.
